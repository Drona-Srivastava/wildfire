# Repository context

This document describes the repository as it exists in this checkout. It is intended as a practical map for someone starting work here. The project name used by the simulation and report is **IGNIS / IGNIS-FORECAST**.

## What this repository contains

There are two related but currently separate technical tracks:

1. **Smoke segmentation (Python/PyTorch):** train a small binary U-Net on labeled aerial images from Boreal Forest Fire Subset C and run it on one image.
2. **Wildfire and UAV simulation (MATLAB/Simulink):** simulate an illustrative cellular fire grid, one-step spread risk, and a waypoint-following survey UAV, with MATLAB and 3D visualizations.

The smoke model is not wired into the simulation. It predicts smoke masks from image pixels; the simulation's fire states are synthetic grid truth. It does not detect flames or map burned area. The repository also has UAV imagery/geospatial examples, archives, and an internship report, but no current pipeline that connects those materials to either executable track.

## Smoke segmentation flow

### Data contract

`src/train_smoke.py` sets repository-relative paths, so invoke it from any working directory with the script path or run the documented commands at the root. The expected extracted root is:

```text
data/raw/Boreal-Forest-Fire/Boreal-Forest-Fire-Subset-C/
```

For training and validation it pairs `images/<split>/<stem>.(jpg|jpeg|png)` with `sam_masks/<split>/<stem>.png`. Images are converted to RGB, bilinearly resized to a square, scaled to `[0,1]`, and transposed to channel-first tensors. Masks are grayscale, resized with nearest-neighbor, thresholded at 128, and treated as binary. Files without a matching mask are skipped; if a split has no matching pairs, loading fails with `FileNotFoundError`.

The intended split use is:

- `train`: SAM-generated masks for optimization.
- `valid`: SAM-generated masks for checkpoint selection.
- `test`: manual masks, used only with `--evaluate` as a held-out final evaluation.

The root README records 1,150 paired training samples (34 missing masks skipped), 227 validation pairs (21 missing masks skipped), and 40 manual test pairs. SAM masks are pseudo-labels; manual test labels have a different annotation source. Reported historical checkpoint metrics are validation Dice 0.8469 at epoch 13 and manual-test Dice 0.7233. These figures describe the documented checkpoint/run and should not be assumed for a newly trained model without rerunning evaluation.

### Model and training

`SmokeUNet` is a compact U-Net. Each encoder/decoder stage uses two 3x3 convolutions with batch normalization and ReLU. Max pooling reduces spatial resolution in four encoder steps; transpose convolutions upsample, and skip connections concatenate corresponding encoder features. A 1x1 convolution emits one logit per pixel. The default channel width is 16.

Training uses binary cross-entropy with logits, AdamW (`lr=1e-3`), and a sigmoid-at-0.5 Dice score. Random seeds are set for Python, NumPy, and PyTorch. CUDA is selected when available; automatic mixed precision and a gradient scaler are enabled on CUDA only. Every epoch evaluates the validation split, and only the best validation Dice checkpoint is saved. The checkpoint is a dictionary with the `model` state, input `size`, best `epoch`, and `val_dice`.

Commands from the root (see `README.md`):

```powershell
py src\train_smoke.py --epochs 1
py src\train_smoke.py --epochs 20
py src\train_smoke.py --size 256 --batch-size 4
py src\train_smoke.py --evaluate
py src\predict_smoke.py path\to\image.jpg --output prediction.png
```

The training defaults are 20 epochs, batch size 8, size 128, and seed 42. `--evaluate` loads the checkpoint and evaluates only `manual_masks/test`; `--size` must match the checkpoint's effective training size for equivalent evaluation. Note that the evaluation branch currently uses the CLI `--size`, while prediction reads `size` from the checkpoint automatically.

### Inference

`src/predict_smoke.py` imports `SmokeUNet` and `CHECKPOINT` from the training module. It loads the saved model, resizes an input image to the checkpoint size, thresholds sigmoid logits at 0.5, resizes the binary output to the original image dimensions using nearest-neighbor, and saves an 8-bit mask. The default destination is `smoke_prediction.png` relative to the current working directory. The checkpoint must exist and match the architecture in `train_smoke.py`.

## Wildfire/UAV simulation flow

The simulation's model contract and caveats are described in more detail in `simulation/README.md`. It uses a 40x40 grid at 10 m per cell (400 m square), with array row 1 north and increasing column east. Grid x is east and y north. Fire states are 0 unburned, 1 burning, and 2 burned; ignition begins at row 20, column 20. The solver runs fixed-step at 1/60 s, while spread updates once per simulated second. The documented batch scenario runs for 300 s.

### Model behavior and limits

The core builder creates constant wind direction/speed, humidity, temperature, patterned fuel, and synthetic elevation inputs. The fire automaton is an illustrative deterministic 8-neighbor rule with wind, humidity, temperature, fuel, and slope modifiers; burning cells remain active for 15 seconds before becoming burned. A separate next-cell forecast scores unburned neighbors using the same factors and emits a risk map and highest-risk candidate. It is a heuristic estimate, not calibrated fire physics or a safety prediction.

The UAV block follows waypoints on the same grid at a nominal 50 m altitude. It includes simple wind disturbance, ground speed and heading, battery depletion/return logic, and a footprint-based idealized sensor. Observations report grid states and estimated grid centroids; unknown cells use 255. This sensor does not run the smoke U-Net or process camera pixels. The dashboard ranks 8x8 sectors, each 5x5 cells (50 m square), with an independence approximation across cell risks.

There are two visualization paths. The live dashboard renders the changing cellular map. The native UAV Scenario scene contains stylized terrain, trees, and a static fire landmark. The Unreal/Simulink 3D Animation viewer uses MATLAB's built-in Empty scene, so it displays the UAV and sky rather than live forest/fire. The vehicle is kinematic, not a six-degree-of-freedom aerodynamic/rotorcraft simulation.

Run from MATLAB at the repository root:

```matlab
addpath('simulation'); run_ignis_sim
```

For interactive viewing in MATLAB Desktop:

```matlab
addpath('simulation'); launch_visual_ignis
```

The README also gives a Windows `matlab -batch` form. Required products and tested release are listed in `README.md` and `simulation/README.md`; the visual builder depends on UAV Toolbox and Simulink 3D Animation in addition to Simulink and related MATLAB products.

## Data and supporting artifacts

The extracted Subset C tree includes `images`, `sam_masks`, `manual_masks`, and `labels`, each split into train/valid/test folders as supplied. Current Python code consumes only images plus SAM masks for train/validation and images plus manual masks for test. `labels/` is not read by these scripts. Do not treat it as the segmentation target. Large dataset archives and imagery at the top level are source/supporting assets and are not automatically used by the current scripts.

`BurnedAreaUAV_dataset_v1.rar` is reserved for future burned-area work; the smoke U-Net does not consume it. The repository README references the Boreal dataset DOI and the BurnedAreaUAV Zenodo record for provenance. Check archive contents and licenses before redistributing extracted data.

## Generated files and portability

`.gitignore` excludes Python bytecode/cache, `models/*.pt`, and `outputs/`. The checkpoint is needed for inference and evaluation but is not covered by version control under this ignore rule; preserve or regenerate it when moving to another checkout. Training writes its best checkpoint to `models/smoke_unet.pt`. Prediction writes a mask to the chosen `--output` path (default relative to current directory). MATLAB creates/updates `simulation/results/starter_run.mat` and may update the `.slx` model and cache directories during builds/runs. `slprj/` and `.slxc` are MATLAB-generated data, not source code.

The current project has no Python dependency manifest in the root. The README states the working environment has PyTorch with CUDA support, Pillow, and NumPy. MATLAB product requirements are documented in the two README files. Paths used by the Python scripts are resolved relative to `src/train_smoke.py`, while output paths for prediction are relative to the process working directory unless absolute paths are supplied.

## Suggested orientation for future changes

- For smoke dataset pairing, preprocessing, architecture, loss, checkpoint selection, or evaluation, start in `src/train_smoke.py`.
- For per-image inference and mask output behavior, start in `src/predict_smoke.py`.
- For fire propagation, weather inputs, risk forecast, UAV controller, and model wiring, start in `simulation/build_ignis_sim.m`.
- For scenario geometry and native UAV scene motion, start in `simulation/setup_ignis_uav_scenario.m` and `simulation/build_ignis_uav_scene.m`.
- For live display changes, start in `simulation/ignis_fire_viewer.m`.
- For the simulation's supported run paths and limitations, consult `simulation/README.md` before changing assumptions.
- Keep smoke inference, synthetic fire-grid state, and burned-area segmentation semantically separate unless a deliberate, documented integration is implemented.
